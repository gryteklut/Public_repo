<Quiz id="az140-d10-q1">
Pooled profiles are FSLogix containers on Azure Files. A session host is rebuilt from the gallery image. What must you restore for the user to see yesterday's files?

- [x] The file share that holds the profile containers
- [ ] The session host OS disk
- [ ] The host pool RDP properties
- [ ] The Log Analytics workspace

The profile is not on the OS disk. Rebuilding the host from the image is normal. The container on the share is the profile. Personal desktops are the case where the virtual machine itself may hold user data, and those disks are a separate backup target. Image versions are a third target.

[Source: Backup recommendations](https://learn.microsoft.com/en-us/azure/virtual-desktop/disaster-recovery)
</Quiz>

<details class="study-collapse">
<summary>Study this topic</summary>

Design three backups: FSLogix share (profiles and often Office containers), personal desktop disks, and image versions or the gallery. Azure Backup on the storage account covers the share. Azure Site Recovery is for replicating virtual machines to another region, not for mounting a profile VHD by itself.

</details>

<Quiz id="az140-d10-q2">
The business requires a second Azure region if the primary region fails. Which design is valid?

- [x] A second host pool in the other region, with profile storage that the recovered users can mount, and image versions replicated there
- [ ] One host pool stretched across two regions
- [ ] A Private Link endpoint in the second region and no other resources
- [ ] Turning on RDP Multipath

Host pools are deployed in one region. You plan another host pool (active/active or active/passive), how profiles move or replicate, and how clients find the surviving feed. Multipath keeps a session up across network paths. It is not a regional disaster-recovery plan.

[Source: Multi-region for Azure Virtual Desktop](https://learn.microsoft.com/en-us/azure/virtual-desktop/disaster-recovery)
</Quiz>

<details class="study-collapse">
<summary>Study this topic</summary>

Cloud Cache can point a profile at storage in two regions. Gallery replication places the image near the second host pool. Document which region is primary and how you tell users which workspace to open. Update strategy is separate: in-place updates versus a new image version and new hosts.

</details>

<Quiz id="az140-d10-q4">
A pooled user on an Entra-joined host gets a new session host after autoscale replaces the previous one. Their desktop icons are missing. The image is correct. Where do you look first?

- [x] The FSLogix share: the profile container did not mount
- [ ] The RemoteApp application group
- [ ] RDP Multipath
- [ ] The management group

Icons and documents in a pooled pool live in the profile container. A new host with the right image still looks empty until FSLogix mounts the VHD. Check share permissions, Entra Kerberos or the directory the share expects, and `VHDLocations` or Cloud Cache. RemoteApp would hide the desktop entirely, not just the icons.

[Source: FSLogix profile containers](https://learn.microsoft.com/en-us/azure/virtual-desktop/fslogix-profile-containers)
</Quiz>
