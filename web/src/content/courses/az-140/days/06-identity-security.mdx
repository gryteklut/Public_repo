<Quiz id="az140-d6-q1">
Which set lists the identity scenarios the AZ-140 study guide measures for session hosts?

- [x] Active Directory Domain Services, Microsoft Entra ID, and Microsoft Entra Domain Services
- [ ] Microsoft Entra ID only, because the other two were removed from the exam
- [ ] Active Directory only, because Entra join cannot host a session
- [ ] Microsoft accounts and a local administrator password

You pick the model that matches the environment. Entra ID join is fully supported and is what the current labs use. AD DS is still the hybrid and Kerberos-heavy option. Entra Domain Services is the managed domain option. The exam asks which requirements go with which choice.

[Source: Identity in Azure Virtual Desktop](https://learn.microsoft.com/en-us/azure/virtual-desktop/authentication)
</Quiz>

<details class="study-collapse">
<summary>Study this topic</summary>

Entra-joined hosts sign users in with Entra accounts and support single sign-on. Domain-joined hosts need line-of-sight to domain controllers and DNS. Entra Domain Services is not the same thing as Entra ID join. Passwordless, smart card, and multifactor authentication are all in this skill.

</details>

<Quiz id="az140-d6-q2">
You must require multifactor authentication when users connect to Azure Virtual Desktop. What do you configure?

- [x] A Conditional Access policy that targets the Azure Virtual Desktop cloud app
- [ ] An NSG rule that allows TCP 3389 from the internet
- [ ] A QoS policy with DSCP 46
- [ ] An FSLogix Office container

Conditional Access uses the Azure Virtual Desktop app as the target, then a grant control such as multifactor authentication. You can also require a compliant device. An NSG does not perform MFA.

[Source: Conditional Access for Azure Virtual Desktop](https://learn.microsoft.com/en-us/azure/virtual-desktop/set-up-mfa)
</Quiz>

<details class="study-collapse">
<summary>Study this topic</summary>

Single sign-on for Entra-joined session hosts changes how often the user sees a prompt. Plan the policy so it covers the client (Windows App or the web client) and does not lock out the service accounts that register session hosts. Per-user MFA is the older switch. Conditional Access is the control the study guide names.

</details>

<Quiz id="az140-d6-q3">
A user should see a published desktop and nothing else in the subscription. Which role fits?

- [x] Desktop Virtualization User on the application group
- [ ] Owner on the subscription
- [ ] Desktop Virtualization Host Pool Contributor
- [ ] Virtual Machine Contributor on every session host

Desktop Virtualization User is the role for using desktops and apps. Host Pool Contributor and Virtual Machine Contributor are management roles. Owner is far too broad.

[Source: Built-in Azure Virtual Desktop roles](https://learn.microsoft.com/en-us/azure/virtual-desktop/rbac)
</Quiz>

<details class="study-collapse">
<summary>Study this topic</summary>

Split admin roles the same way the resources split: host pool, application group, workspace, and session hosts. Local group membership on the session host is a separate decision (who is a local admin inside Windows). The exam asks for both Azure RBAC and the rights on the session host.

</details>

<Quiz id="az140-d6-q4">
Administrators must reach a session host to troubleshoot it. Users connect only through Azure Virtual Desktop. What do you use for the administrators?

- [x] Azure Bastion or just-in-time VM access, with no public RDP port
- [ ] An inbound NSG rule for TCP 3389 from Any
- [ ] RDP Multipath as the admin jump host
- [ ] A Conditional Access exclusion for all administrators and a public IP

Bastion and just-in-time access are the study-guide options for administrative access. User sessions do not need a public RDP port. App Control for Business (WDAC) and Controlled Folder Access protect what runs on the host. Defender for Cloud, Defender Antivirus, and Defender for Endpoint are the other security layers, and they are not interchangeable.

[Source: Azure Bastion](https://learn.microsoft.com/en-us/azure/bastion/bastion-overview)
</Quiz>

<details class="study-collapse">
<summary>Study this topic</summary>

Network security for the session host subnet is NSGs, user-defined routes, and Azure Firewall, including the required outbound endpoints. Trusted Launch and confidential VMs are host security types from the infrastructure skills. Do not treat Defender Antivirus definition updates as a substitute for Defender for Endpoint onboarding.

</details>
