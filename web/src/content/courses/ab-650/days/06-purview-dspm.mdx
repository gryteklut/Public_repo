<Quiz id="ab650-d6-q1" shuffle={true}>
Staff must be stopped from pasting credit-card numbers into Microsoft 365 Copilot prompts. Classifying a document later is not enough. What should you configure?

- [ ] A sensitivity label that a user may apply by hand to a finished document
- [ ] A retention policy that keeps Copilot prompts and responses for seven years
- [x] A DLP policy that includes the Microsoft 365 Copilot location and that card type
- [ ] The DSPM for AI recommendations page, with no blocking policy behind it

A DLP policy can evaluate Copilot prompts and block or restrict sensitive info such as credit-card numbers. A sensitivity label classifies an item. It does not by itself stop the prompt. Retention keeps content. DSPM for AI shows posture and recommendations. It is not the policy that blocks.
</Quiz>

<Quiz id="ab650-d6-q2" shuffle={true}>
You created a sensitivity label named Confidential. Users do not see it in Word. The label exists in Purview. What is missing?

- [ ] A DLP rule that uses the label name as its only sensitive information type
- [ ] An attack simulation that teaches every user the label's display name
- [ ] Company branding text that lists Confidential on the sign-in page
- [x] A label policy that publishes Confidential to those users or groups

A label stays invisible in Office until a label policy publishes it. A DLP rule can act on content. It does not put the label on the Word button. Attack simulation and company branding do not publish labels.
</Quiz>

<Quiz id="ab650-d6-q3" shuffle={true}>
Contracts in one SharePoint library must be kept for seven years, and a reviewer must decide what happens when that period ends. Other libraries are out of scope. What should you use?

- [x] A retention label published to that library, with a disposition review at the end
- [ ] Microsoft 365 Backup on a seven-year schedule, used as the compliance record
- [ ] A Teams meeting policy that retains meeting transcripts for seven years
- [ ] Safe Attachments with a seven-year delay before a file is detonated

A retention label can target that library's items, keep them for the period, and start a disposition review. Backup is how you restore data, not the retention decision. A meeting policy and Safe Attachments do not keep contract files in that library.
</Quiz>

<Quiz id="ab650-d6-q4" shuffle={true}>
Security wants to see Copilot prompts, the sensitive data those interactions touched, and recommended actions. This view itself must not block a prompt. What should they open?

- [ ] Defender for Office 365 Threat Explorer, filtered to Copilot senders
- [x] DSPM for AI in Microsoft Purview
- [ ] Network connectivity insights for the offices that use Copilot
- [ ] The Entra Password Protection custom banned password list

DSPM for AI is the view of AI activity, oversharing, and recommended controls. Opening it does not block a prompt. Blocking is a DLP policy. Threat Explorer investigates mail. Network insights and Password Protection are unrelated to prompt content.
</Quiz>

<Quiz id="ab650-d6-q5" shuffle={true}>
Choose two. Credit-card numbers must be detectable in content, and Finance must see a label they can apply in Office. Which two pieces meet those needs?

- [ ] A retention policy, because it both detects card numbers and shows the label in Word
- [x] A sensitive information type or classifier that detects credit-card numbers
- [x] A sensitivity label that a label policy publishes to the Finance group
- [ ] An administrative unit named Finance, which publishes labels to its members

A sensitive information type detects the card pattern. The label classifies the item, and the label policy is what makes that label appear for Finance. A retention policy keeps content and does neither of those jobs. An administrative unit scopes admin roles. It does not publish labels.
</Quiz>

<Quiz id="ab650-d6-q6" shuffle={true}>
A DLP alert fired because a user emailed a spreadsheet that matched the credit-card sensitive information type. You need to understand the match before you change any policy. What should you review?

- [ ] The user's eligible PIM roles, because a DLP alert cannot be opened until a role is activated
- [ ] Service health for Exchange Online, because each DLP alert is a service incident
- [ ] The user's attack-simulation click rate from the last phishing campaign
- [x] The matched sensitive info, the user, and the activity that triggered the alert

Triage starts with what matched, who did it, and which activity triggered the policy. From there you notify, mark a false positive, or escalate. PIM activation, service health, and a phishing click rate do not explain this match. Deleting the policy is not the first response.
</Quiz>
