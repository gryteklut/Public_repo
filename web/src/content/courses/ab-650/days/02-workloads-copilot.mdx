<Quiz id="ab650-d2-q1" shuffle={true}>
Copilot drafts answers from a budget file on a SharePoint site. Finance must still open that file, and Copilot should stop using it. What should you change?

- [ ] Remove Finance permission so nobody, including Copilot, can open the file
- [ ] Create a Conditional Access policy that blocks SharePoint for Finance
- [x] Restrict discovery of that site so Copilot does not ground on it
- [ ] Turn off Microsoft 365 Backup so Copilot cannot restore the file into answers

Copilot grounds on content the signed-in user is allowed to open. Restricted content discovery stops Copilot from using the site while people who already have permission can still open the file. Removing permission blocks Finance from the file they still need. Conditional Access would block the app, not one site. Backup is a restore tool, not a grounding switch. [Restricted Content Discovery](https://learn.microsoft.com/en-us/sharepoint/restricted-content-discovery)
</Quiz>

<Quiz id="ab650-d2-q2" shuffle={true}>
During a Copilot rollout, search and Copilot must use only an approved list of SharePoint sites, not every site a user can open. What should you use?

- [ ] A retention policy that keeps only the approved sites for seven years
- [ ] Safe Links, so every unapproved site URL is rewritten at click time
- [ ] An administrative unit that contains the approved SharePoint sites
- [x] Restricted SharePoint Search with those approved sites allowed

Restricted SharePoint Search limits enterprise search and Copilot retrieval to an allow-list of sites. A retention policy keeps or deletes content. Safe Links checks URLs in mail and documents. An administrative unit scopes a directory role. It does not build a SharePoint search allow-list.
</Quiz>

<Quiz id="ab650-d2-q3" shuffle={true}>
Organizers say Copilot is unavailable in Teams meetings, and transcripts are not being created. Meeting chat otherwise works. What should you check first?

- [x] The Teams meeting policy that allows transcription and Copilot
- [ ] A Purview retention label on the organizer's mailbox
- [ ] The Exchange anti-malware policy for files posted in meeting chat
- [ ] Whether the tenant has a custom banned password list

Copilot in a Teams meeting depends on transcription being allowed by the meeting policy. A retention label preserves mailbox content. Anti-malware scans files. Password Protection rejects weak passwords. None of those turn meeting transcription on.
</Quiz>

<Quiz id="ab650-d2-q4" shuffle={true}>
A project site was deleted yesterday and the owner needs the files back this week. Compliance also requires contracts to be kept for seven years. Which tool restores the deleted site?

- [ ] A Purview retention policy scoped to SharePoint sites
- [x] Microsoft 365 Backup, then a restore of the site from a backup point
- [ ] Attack simulation training with a payload that names the site
- [ ] DSPM for AI, using a recommended control to recreate the files

Microsoft 365 Backup is the operational restore for Exchange, SharePoint, and OneDrive. A retention policy can preserve content for a compliance period, and it is not the same restore product. Attack simulation and DSPM for AI do not bring a deleted site back.
</Quiz>

<Quiz id="ab650-d2-q5" shuffle={true}>
Choose two. Finance must keep opening a sensitive site, but Copilot must stop grounding on it. Separately, Teams meetings should be allowed to produce a transcript so Copilot can work in the meeting. Which two actions match?

- [x] Restrict discovery on the sensitive site without removing Finance permission
- [ ] Delete the Finance users so Copilot has no identity left to ground with
- [x] Allow transcription in the Teams meeting policy used by those meetings
- [ ] Disable service health notifications so Copilot ignores the sensitive site

Discovery restriction and the meeting transcription policy solve two different requirements. Deleting users removes people, not a grounding setting. Service health notifications do not change which files Copilot can read.
</Quiz>

<Quiz id="ab650-d2-q6" shuffle={true}>
A guest opens project files through a sharing link, and Copilot answers from those files when that guest asks. The guest must stop seeing the files. What should you change?

- [ ] Company branding, so the guest sees a warning on the sign-in page
- [ ] A service health notification that mentions the project site name
- [x] The SharePoint permission or sharing link that grants the guest access
- [ ] Network connectivity insights for the guest's home office

Copilot follows the access the person already has. Remove or narrow the sharing link or the site permission. Branding, a service health notice, and a network report do not revoke the file.
</Quiz>

<details class="study-collapse">
<summary>Study this topic</summary>

Copilot grounding follows SharePoint permissions. Restricting discovery, or using Restricted SharePoint Search, is a different task from taking away the permission to open the file. Teams meeting Copilot needs transcription allowed in the meeting policy. Microsoft 365 Backup restores content. It does not replace Purview retention.

</details>
